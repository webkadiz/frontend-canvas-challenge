# Тестовое задание: канвас на React Flow

## Решение

**Поток** — редактор цепочек «текст → генератор → результат» на React 19,
TypeScript, Vite и React Flow (`@xyflow/react`).
Генерация использует только локальное изображение API. Для переименования пространства
добавлен `PUT /api/spaces/:spaceId` с телом `{ "title": "Новое название" }`.
Название сохраняется на сервере отдельно от графа; его ETag и история undo/redo не меняются.
Создание и переименование открываются в общем диалоге (кнопка карандаша рядом с названием).

### Запуск решения

Из корня репозитория, Node.js 24.x и npm 11.x:

```sh
npm ci
npm run dev
```

API: http://127.0.0.1:4001. Frontend: http://127.0.0.1:5174.
Оба процесса останавливаются Ctrl+C. Создайте пространство и нажмите
«Добавить пример цепочки» либо добавляйте ноды из панели слева.

```sh
npm run dev:api
npm run dev:web
npm run build
npm run test:web
npm run check
npm run smoke          # при запущенном API
```

Для просмотра сборки: `npm start` и отдельно `npm run preview -w @canvas/web`.
Vite проксирует `/api` и `/assets/demo.svg` в API. Для другого адреса измените
`apps/web/vite.config.ts` либо задайте `VITE_API_URL` при запуске/сборке.
Ссылки изображений разрешаются относительно того же базового адреса.

### Устройство

- `src/lib/http.ts`: общий транспорт, JSON, пустые ответы, метаданные ответа,
  нормализованные сетевые/HTTP/parse-ошибки. Здесь ресурс приходит без envelope;
  API-функции в `src/api.ts` знают особенности endpoints. Компоненты не разбирают HTTP.
- `src/model/graph.ts`: индекс типов и смежности, единое правило допустимости связей,
  готовность цепочки, выбор актуальной попытки для каждого результата.
- `src/model/save-queue.ts`: самостоятельная очередь сохранений с debounce, ETag,
  ревизиями локального графа и восстановлением потерянного ответа.
- `src/model/canvas.ts`: пространства, граф и генерации. Операции изменения данных
  и временные поля React Flow разделены. Канонический GraphData содержит только
  nodes, edges, viewport; selected, measured, dragging и callbacks не отправляются.
- `src/lib/async.ts`: последовательный polling с отменой. Каждая генерация имеет
  собственный AbortController; уход из пространства останавливает все опросы.
- `components/nodes/`: переиспользуемая оболочка, отдельные компоненты нод и функции отображения состояний.
  memo и подписки на конкретную попытку/результат ограничивают лишние обновления.

### Debounce, очередь и конфликты

Правка мгновенно меняет локальный immutable-граф и увеличивает ревизию.
Через 500 мс после последней правки очередь отправляет снимок. На один граф одновременно
выполняется не более одного PUT. Ответ обновляет ETag и подтверждённую ревизию,
но **не заменяет локальный граф**. Новые правки сохраняются следующим запросом
с ETag предыдущего ответа. Выделение ноды и измерения React Flow не запускают сохранение.

Кнопка генерации вызывает `flush()`: отменяет debounce, ждёт уже отправленный PUT,
досохраняет новые ревизии и только после этого запускает генерацию с полученным ETag.
При ошибке сохранения POST генерации не отправляется.

При 412 очередь останавливается, локальные правки остаются в памяти и черновике
localStorage. Можно скачать JSON или явно перечитать серверный граф.
Предыдущий черновик остаётся доступен для восстановления; автоматического слияния нет.
Если ответ PUT потерялся, очередь читает сервер и сравнивает его с отправленным снимком:
совпадение подтверждает сохранение; другая серверная версия означает конфликт;
неизменённая версия допускает явный повтор.

Перед POST генерации сохраняются неизменяемые тело и Idempotency-Key.
Сетевой повтор использует их же даже после новых правок текста.
Для новой попытки создаётся новый ключ. 202 означает ожидание, а failed — результат
операции, не HTTP-ошибку. При восстановлении читаются граф и список генераций;
processing продолжает отслеживаться. Изображение показывается только в исходном
resultNodeId при сохранившейся связи с генератором и отсутствии более новой попытки.
Старый успех не замещает новую ошибку или новую обработку.

### Обработка графа и стоимость

Частый путь `editText(id, text)` вызывается на ввод символа.
Индекс ID → позиция строится при изменении топологии за O(N + E), а при вводе
и перетаскивании переиспользуется. Поиск изменяемой ноды — Map.get, O(1).
Одна необходимая копия массива nodes (`slice`, O(N)) сохраняет порядок и immutable
состояние. Создаются новая нода, её data и оболочка графа; все остальные ноды,
edges и viewport сохраняют ссылки. Поиска find внутри map и копирования всех data нет.
JSON для запроса/черновика создаётся при сохранении, а не на каждом вводе.
При конфликте черновик дополнительно обновляется на каждую правку для сохранности.

Перемещение обрабатывает пакет позиций одним обходом нод; создаются объекты только
для изменённых позиций. Удаление одним проходом по каждой коллекции собирает плотные
массивы нод и оставшихся связей; затем индекс обновляется один раз.
React Flow отдельно получает оформление выделения; эти поля не попадают в GraphData.

### Проверки и границы

Автотесты: debounce 500 мс, одиночная правка и серия, медленный PUT, несколько flush,
актуальный If-Match, отсутствие потери новых правок, 412 и сохранение черновика,
потерянный PUT и сверка снимка, повтор сети, сохранение перед генерацией,
идемпотентность генерации, отказ/новая попытка, восстановление результатов/processing,
закрытие polling, неверные связи, каскадное удаление связей, переподключение результата,
приоритет новой попытки. Общий транспорт и polling также имеют отдельные тесты.
Backend-тесты и OpenAPI проверяются общим `npm run check`.

Ручная проверка: создание пространства, пример цепочки, генерация, отказ и повтор,
редактирование текста, перемещение/связи через порты, сохранение и перезагрузка.
Основной интерфейс рассчитан на desktop 1280 px. Кроме drag-and-drop,
есть форма соединения нод с клавиатуры, кнопки удаления и стандартные клавиши React Flow.

Ограничения: максимум 20 нод и 20 связей по контракту. Нет undo/redo, совместного
редактирования, мобильного канваса и автоматического слияния конфликтов.
В localStorage остаётся последний локальный черновик пространства и нерешённые
идемпотентные попытки; история всех редакторских действий не ведётся.
Деплой не выполнялся.

## Запуск

Потребуются Node.js 24.x и npm 11.x. База данных и ключи внешних сервисов не нужны.

```sh
git clone https://github.com/instatdigital/frontend-canvas-challenge.git
cd frontend-canvas-challenge
npm ci
npm run dev
```

Swagger: [http://localhost:4001/docs/](http://localhost:4001/docs/). Спецификация: [http://localhost:4001/openapi.json](http://localhost:4001/openapi.json) и [файл в репозитории](docs/openapi.json).

В Swagger создайте пространство через `POST /api/spaces`, затем получите его граф. Авторизация не нужна. Все пространства видны в одном локальном экземпляре сервера.

## Структура и команды

```text
apps/api/             бэкенд
apps/web/             ваш фронтенд
packages/contracts/   схемы API и типы TypeScript
docs/                 задание и документация
scripts/              проверки
```

Frontend называется `@canvas/web`. `npm run dev` запускает API и frontend вместе.

Стили интерфейса подключаются через CSS Modules (`*.module.css`), условные классы — через `classnames`.
Общие стили приложения находятся в `apps/web/src/App.module.css`, стили диалога пространства и зума — рядом с компонентами.
В `apps/web/src/global.css` остаются базовые стили страницы и переопределения React Flow.
Служебные классы React Flow `nodrag` и `nowheel` передаются обычными строками: библиотека использует их для обработки событий.

```sh
npm run check       # форматирование, сборка, тесты, OpenAPI
npm run build
npm start           # собранный бэкенд
npm run smoke       # проверка по HTTP; API должен работать
```

## Настройки

Адрес по умолчанию — `127.0.0.1:4001`. При необходимости скопируйте `.env.example` в `.env` и измените `PORT`. Для проверки другого адреса: `BASE_URL=http://localhost:4101 npm run smoke`.

Фронтенд может работать на любом HTTP-порту `localhost`, `127.0.0.1` или `[::1]`. Другие адреса задаются в `CORS_ORIGINS`. Cookies не нужны.

Данные сохраняются в `.data/store.json`. Используйте один процесс API на один файл. Для сброса остановите сервер и выполните `npm run data:reset`. Если меняли `DATA_FILE`, свой файл удалите вручную при остановленном сервере.

Генерация тестовая: после заданной задержки сервер возвращает локальное SVG-изображение или ошибку сценария. Внешних запросов и списаний нет.

Корневые команды сборки и тестов проверяют API и frontend. Зависимости закреплены в корневом `package-lock.json`, типы API импортируются из `packages/contracts`.
