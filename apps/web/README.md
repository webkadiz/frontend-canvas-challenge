# Поток — frontend

React + TypeScript + React Flow, сборка Vite. Из корня репозитория: `npm ci`, затем `npm run dev`.
Интерфейс: http://127.0.0.1:5174, API: http://127.0.0.1:4001.
`npm run build` собирает оба приложения, `npm run test:web` проверяет frontend.
Архитектура и сохранения — в [README решения](../../README.md#решение).

## Структура интерфейса

Компоненты, утилиты, классы и их методы сопровождаются коротким JSDoc на русском:
назначение и важные условия работы, без пересказа сигнатуры и очевидных операций.

Обработчики событий и другие callback-пропсы JSX вынесены в именованные функции.
Для элементов списков функции привязывают нужный идентификатор, а типы обработчиков
переиспользуются из `*.types.ts`. Проверка структуры не допускает inline-функций
в JSX-атрибутах.

Объектные типы и именованные объявления вынесены в соседние `*.types.ts`.
Пропсы названы по компонентам, например `SpaceTitleDialogProps` и `NodeSelectProps`.
Общие пропсы состояния переиспользуются через
`components/shared.types.ts`; компоненты и модели импортируют типы через `import type`.
Проверка структуры исходников запрещает возвращать объявления типов и анонимные
объектные аннотации в файлы с логикой.

- `src/App.tsx` собирает шапку, боковую панель и рабочую область; жизненный цикл страницы вынесен в `src/hooks/useCanvasLifecycle.ts`.
- `src/components/` содержит отдельные блоки палитры, создания связей, панели инструментов и черновиков. Компоненты нод находятся в `src/components/nodes/`.
- `src/constants/` содержит статические тексты интерфейса, ошибки, доступные подписи и конфигурации. `palette.ts` задаёт тип, иконку, название и подсказку каждого блока; `generation.ts` — подписи состояний генерации.
- Тексты, зависящие от параметров, задаются функциями в константах. Пользовательские названия, промпты и данные API остаются данными, а не копируются в словарь.

Новые надписи добавляйте в соответствующий файл `constants`, настройки повторяемых элементов — в именованные объекты вне JSX. Тест `source-structure.test.ts` проверяет отсутствие русских строк вне констант и массивов конфигурации, создаваемых непосредственно перед `.map()` внутри JSX.

В панели канваса доступны undo/redo и масштаб. История хранит 50 действий текущего
пространства до перезагрузки: ноды, связи, текст и позиции. Ввод текста за один фокус
и перетаскивание группируются; камера, зум и серверные генерации не отменяются.
Ctrl/Cmd+Z отменяет действие, Ctrl/Cmd+Shift+Z (или Ctrl+Y) возвращает его.
Внутри полей ввода работают стандартные текстовые сочетания клавиш.
Undo/redo сохраняются обычной очередью автосохранения; смена пространства очищает историю.
Зум и перемещение камеры сохраняются через API с тем же debounce 500 мс, но не
добавляют действия в undo/redo и не включают индикатор несохранённых правок контента.
Ошибки и конфликты фонового сохранения камеры показываются явно.

## SCSS, иконки и линтеры

Стили находятся в `global.scss` и `*.module.scss`; Vite компилирует их через `sass`.
Сохранены CSS Modules, `classnames` и camelCase-классы. Связанные селекторы сгруппированы
с неглубокой вложенностью; CSS React Flow подключается из библиотеки без изменений.

Иконки палитры, удаления, переименования, undo/redo и зума — именованные импорты
`lucide-react`. Декоративные иконки скрыты от скринридера, подписи кнопок сохранены.

`npm run lint -w @canvas/web` из корня запускает ESLint и Stylelint. Доступны также
`lint:code` и `lint:styles`. ESLint проверяет TypeScript, правила React Hooks,
неиспользуемые переменные, шаблонные строки и разделение объявлений пустой строкой.
Stylelint проверяет SCSS, camelCase и глубину вложенности, допускает CSS Modules
`composes` и глобальные классы React Flow. Prettier отвечает за форматирование.
Конфигурации и зависимости объявлены в `apps/web`; корневой lock-файл обновлён для workspace.

## Общий код и стоимость обработки

`src/lib/http.ts` отвечает за отправку, заголовки, HTTP-статусы, разбор ответа и
нормализацию ошибок. `src/api.ts` описывает типизированные операции. Модель
`src/model/canvas.ts` управляет пространством и генерациями; переиспользуемый
`poll` в `src/lib/async.ts` — ожиданием и отменой опроса. Компоненты не разбирают
HTTP-ответы. `SaveQueue` отделяет debounce и последовательную запись с ETag от UI.

Реальный горячий участок — перемещение нод: `Canvas.positions` вызывается на
кадрах перетаскивания. Один проход по N нодам и O(1)-поиск позиции в `Map`;
копируется массив ссылок, а объект — только у действительно изменённой ноды.
Индексы связей при этом не перестраиваются. Координаты ограничиваются до
сравнения: повторные движения за границей не вызывают сохранение или историю.

Undo/redo разделяет неизменяемые массивы и объекты с моделью, без глубокого
клонирования и JSON-сериализации на каждом кадре. Проверка изменения — по ссылкам
с ранним выходом, в худшем случае O(N + E). Снимок создаётся на начало группы
правок; один drag — одно действие. JSON нужен при записи/резервировании после
debounce и сверке неопределённого PUT, а не на каждом движении в обычном сценарии.
Массивы приходят из JSON и создаются без дырок; обработка опирается на плотные
массивы объектов, а не на оптимизации числовых массивов конкретного движка.

## Проверки отказоустойчивости

Состояния генерации определены в `src/model/generation-state.ts`. Потерянный POST
остаётся в `uncertain`: сохранённые в `localStorage` тело и ключ повторяются точно,
даже после перезагрузки или редактирования графа. Уже обрабатываемую генерацию
нельзя повторно запустить; ошибка опроса отделена от отказа генерации и позволяет
продолжить проверку без нового POST.

Очередь сохранения выдерживает 500 мс тишины, отправляет один PUT одновременно и
объединяет следующие правки. Перед генерацией выполняется `flush`. При потерянном
ответе PUT контрольный GET сверяет отправленный снимок; при 412 локальный граф
остаётся доступен для скачивания и явного восстановления. Индексы `Map`
перестраиваются только при изменении состава нод/связей, а не на каждом вводе или
движении ноды. Результат принадлежит текущей связи и последней попытке генерации.

Черновик конфликта хранится отдельно от очереди новых правок: сохранение серверной
версии не удаляет его, и он доступен после перезагрузки. Восстановление сначала
резервирует возвращённый граф, затем убирает отдельную recovery-копию. Если POST
создания пространства подтверждён, а следующий GET упал, повтор открывает уже
созданное пространство, в том числе при повторной отправке диалога.

Эти условия покрыты `npm run test:web`, включая двойной запуск, потерю ответа с
reload, медленный PUT, 412, изменение связей во время опроса и стабильность индексов.

Для короткого E2E-набора из корня:

```sh
npx playwright install chromium
npm run test:e2e
```

Два сценария на ширине 1280: потерянный PUT перед генерацией с восстановлением
результата после reload; конфликт 412 с сохранением и восстановлением локального
черновика. Серверы используют отдельные порты 4101/5274 и API в памяти, без
пользовательской `.data`. Playwright запускается отдельно от `npm run check`;
список сценариев: `npm run test:e2e -- --list`.

Проверка только frontend (из корня, после установки зависимостей и первоначальной
сборки готового API/контрактов): `npm run build -w @canvas/web` и
`npm run test:web`. Эти команды не пересобирают backend.

## Ограничения

- Нет автоматического слияния конфликтов: пользователь выбирает серверный граф
  или восстановление локального. Черновики зависят от доступности localStorage.
- У создания пространства нет предусмотренного API ключа идемпотентности. Если
  потерян именно ответ POST, нельзя достоверно отличить созданное пространство
  от неотправленного запроса. Гарантия повтора без нового POST действует после
  подтверждённого создания; backend ради этого не изменяется.
- История ограничена 50 действиями и живёт до закрытия пространства; авторизация,
  совместная работа и полноценная мобильная версия не входят в задание.
